| TP-048 | 2026-09-29 | Lock and unlock run inside a Firestore **transaction**, not a re-read-then-batch. A manual admin lock and the Wednesday auto-lock can overlap (the admin taps Lock right as `weeklyAutomation` runs); a plain re-read guard before a batch write can't stop both from passing the check and applying every player's Elo delta twice. A transaction's reads become its own write-conflict check — if the week (or anything else it read) changed between the read and the commit, Firestore aborts and retries the whole callback, so a losing concurrent attempt re-reads the now-locked week and is refused instead of double-applying | A re-read guard only catches a conflict that already happened *before* the guard's own read; it can't catch one that happens between that read and the write that follows it.
